# Голос зала

Бот MAX передаёт сообщения в очередь ведущего. На экране видны до десяти последних одобренных сообщений без имён. Реакции из кнопок бота всплывают сразу.

[Открыть экран на GitHub Pages](https://alekca.github.io/max-message-cloud/)

## Проверка без MAX

Нужен Python 3.9 или новее. В папке проекта запустите:

```sh
export ADMIN_KEY="$(openssl rand -hex 24)"
printf 'Ключ ведущего: %s\n' "$ADMIN_KEY"
python3 server.py
```

Откройте экран на http://127.0.0.1:8000/ и панель ведущего на http://127.0.0.1:8000/admin. Войдите с напечатанным ключом и добавьте текст через «Пробный режим без токена MAX». Одобрите сообщение, запустите реакцию и проверьте экран.

## Подключение MAX

1. Создайте бота в [MAX для партнёров](https://dev.max.ru/docs/chatbots/bots-create/create) и получите его токен.
2. На сервере задайте переменные окружения `ADMIN_KEY` (случайный ключ от 16 символов), `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET` (например, результат `openssl rand -hex 24`) и `MAX_BOT_URL` (публичная ссылка вида `https://max.ru/имя_бота`). Для подключения к API MAX добавьте доверенный сертификат Минцифры в системное хранилище или задайте `MAX_CA_FILE` с путём к PEM.
3. Запустите `python3 server.py` под менеджером процессов. Поставьте перед ним HTTPS-прокси на порту 443 с ограничением размера запроса и таймаутами. По умолчанию сервис слушает `127.0.0.1:8000`. Храните SQLite на постоянном диске, путь задаётся через `DB_PATH`. Используйте отдельную базу для тестов, чтобы пробные сообщения не попали на мероприятие.
4. В том же окружении зарегистрируйте подписку: `python3 server.py subscribe https://ваш-домен/max/webhook`. [Требования MAX к вебхуку](https://dev.max.ru/docs-api/methods/POST/subscriptions).
5. Откройте панель ведущего по адресу `https://ваш-домен/admin`. Для проектора используйте `https://alekca.github.io/max-message-cloud/?server=https%3A%2F%2Fваш-домен` или страницу сервера `https://ваш-домен/?live=1`. На GitHub Pages без параметров открывается демо. Для другого домена страницы укажите её origin в `SCREEN_ORIGIN`.

В GitHub хранятся исходники. Ключи и база остаются на сервере. Одобренный текст доступен любому, кто знает адрес экрана. Используйте отдельную базу для каждого мероприятия и удаляйте её по завершении, если хранить сообщения больше не нужно.
